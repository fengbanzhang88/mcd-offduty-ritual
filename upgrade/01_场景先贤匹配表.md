## 0. 功能定位（先读这段）

- **是什么**：「麦麦下班仪式感」的杀手锏新功能。用户说完下班状态，Skill 除了给一餐**真实存在**的麦当劳，再派一位「先贤」当**今晚的饭搭子**——一句贴心话 + 一幅插画，写进仪式卡片。
- **叫什么**：功能名建议 **「时空饭搭子」**。Slogan：**你的下班饭搭子，可能是两千年前的那位。**
- **接在哪一步**：插在六步工作流的**第 1 步（接住情绪）与第 6 步（出卡片）之间**——情绪识别后立即匹配先贤，卡片渲染时新增「先贤区」。
- **一句话原则**：**先贤负责"被懂"，麦当劳负责"真"。** 文案只养心、不说教、不预测吉凶。

## 3. 匹配算法（给前端工程师）

以下为**已落地口径**（与 `scripts/match_sage.py` 逐条一致，2026-10-13 团长裁定）：

```python
def match_sage(user_text: str, hour: int) -> dict:
    # 0. 安全闸：命中敏感词 → 不走先贤功能（见第 5 节红线）
    if contains_any(user_text, SENSITIVE_WORDS):
        return CRISIS_CARE_RESPONSE

    # 1-3. 计分：情绪词 ×2 + 关键词 ×1；长度 <2 的词一律不计分
    scores = {}
    for s in SCENARIOS:
        score = sum(2 for w in s["emotion_words"] if len(w) >= 2 and w in user_text)
        score += sum(1 for w in s["keywords"] if len(w) >= 2 and w in user_text)
        scores[s["id"]] = score

    # 4. 取最高分；同分取表中靠前者（表已按优先级排序）
    best = max(scores, key=scores.get)

    # 5. 兜底：全部 0 分 → 深夜（22:00–05:00）归 S01，其余归 S04
    if scores[best] == 0:
        best = "S01" if (hour >= 22 or hour < 5) else "S04"

    # 6. 输出：先贤 + 贴心话 + 出场白 + 插画 key，进入原有第 6 步卡片渲染
    return SAGE_TABLE[best]
```

**两条工程规则（改代码前先读）**

1. **长度 <2 的词一律不计分**：中文单字必然是其他词的子串——"气"会命中"天气"、"烦"会命中"麻烦"、"装"会命中"装修"。因此内容侧补词**必须补多字词**（如"好累/累死/生气/被毙/功劳"），单字词进表也不得分。
2. **计分阶段不做深夜时段加成，深夜优先由第 5 步 fallback 承担**。原设计（S01 在 22:00–05:00 额外 +2）已废弃：加成会把明确命中其他场景的用户错分给 S01（典型如深夜想家说"给家里打电话"，本应归 S12）。`time_boost` 字段已从 `sage_match.json` 移除，全仓库无代码读取。

**边界情况**

1. 用户同时说多个场景（如"加班还被骂了"）：按得分走，S01/S02 都可能命中，取高分。
2. 语气反讽（"可真是太好了呢"）：关键词不误判即可，反讽不触发任何先贤也无妨——fallback 会兜住。
3. 二次来访（同用户同一天再来）：允许复用同一位先贤，但 `quote` 可在场景内轮换；不换场景不换人，保持"老熟人"感。
4. `tone` 字段只是默认建议，**用户原话里的调性优先**（原 SKILL 第 4 步逻辑不变）。

## 4. 卡片与插画规范（给插画设计师）

### 4.1 卡片版式与「先贤区」（750×1080）

**正常卡（有插画）——叙事顺序（00 纪要 §5 已采纳）**：

```
标题（你的事）
  ↓
先贤插画带：630×300 横幅画窗带（圆角 + 烫金描边），
            左上压书法题词，左下落款 + 朱文印章
  ↓
先贤贴心话：金色，全卡最大字号
  ↓
文案卡 → 今晚这一餐 → 合计 → 页脚
```

- 插画文件命名：`sage_{sage_id}.png`（如 `sage_zengguofan.png`）。
- **首批只出 9 张先贤通用形象**：每位先贤一张、跨场景复用（同一先贤复用两个场景时共用一个形象文件）；同场景差异化版本列 v1.1，不阻塞首发。
- 贴心话 ≤20 字，渲染前硬校验，超长拒绝渲染并告警（不截断）。
- **硬避让区**：顶栏、标题、文案卡、餐单/价格区、页脚文字、右下二维码/券码区，插画带与题词落款均不得入侵。最终像素坐标以 `03_技术落地方案.md` 为准（画窗带提案 60,216 / 630×300，前端脚本已按此实现）。

**降级路径（00 纪要 §5，两种情况，别混为一谈）**

- **情况 A｜调用里根本没有 `sage` 字段（老调用）**：卡片与改造前**字节级一致**，一行不许坏（有 SHA-256 断言守着）。
- **情况 B｜有 `sage` 字段但插画文件缺失 / Pillow 不可用**：这是全新路径，不存在"现有行为"可被破坏——文案卡内仍须渲染**金色贴心话 + "—— 今晚的饭搭子 · {name}" 小字**，字号沿用 `f_body`，**不得放大成独立大字区，也不得截断**。
- **为什么情况 B 必须显示**：用户说了"功劳被抢了"、系统也正确识别出孔子，卡片上却毫无痕迹——用户只会判定"功能坏了"。这是**功能静默失败**，比版式不完美严重得多。
- 纯文本降级为 `.md` 的策略不变。
